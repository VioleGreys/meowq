# Meowq: Фронты — заметки для Claude

Мобильная глобальная стратегия о Второй мировой войне на Godot 4.7.2 (GDScript;
до ноября 2026 — 4.3, переход без изменений результатов: подписи и хэши совпали).
Цели и этапы — в `ROADMAP.md`. Работаем поэтапно: этап заканчивается рабочей
сборкой, тестами и скриншотами; следующий этап начинаем только после «ок»
пользователя. Общение и тексты в игре — на русском.

## Язык (решение пользователя)
- ВСЕ ответы пользователю — только на русском: итоговые отчёты, короткие
  сообщения о ходе работы, вопросы, пояснения между вызовами инструментов.
  Ни одной фразы на английском (кроме кода, команд, путей и имён).

## Порядок работы с контекстом (решение пользователя)
- В конце каждой задачи, после коммита и пуша, в итоговом отчёте прямо
  рекомендовать: `/clear` (задача закрыта, следующая с ней не связана) или
  `/compact` (следующая продолжает эту — с подсказкой, что сохранить). Команды
  запускает пользователь. Не доводить до автосжатия.
- Перед такой рекомендацией записать всё, что не восстановить из кода
  (решения, причины найденных ошибок, открытые проблемы), — в заметки по
  системе (`docs/notes/*.md`), а не сюда.
- Этот файл загружается в каждую сессию целиком — держать его коротким
  (решение пользователя, ноябрь 2026): здесь только правила, состояние этапов,
  команды проверки и указатель. Подробности по системам — в `docs/notes/`.

## Заметки по системам (`docs/notes/`)
Перед работой над системой прочитать её файл (только нужный); после работы —
дополнить его.
- `history.md` — фокусы, события, шансы, репутация и шкала сил, исторический
  ИИ, дипломатия, данные стран (`history.gd`, `relations.gd`, `diplomacy.gd`).
- `forces.md` — флот, авиация, порты, высадки, конвои (`forces.gd`, `convoys.gd`).
- `military.md` — дивизии, шаблоны из батальонов, ширина фронта, военные заводы (`military.gd`).
- `balance_ai.md` — укрепления, зима, акклиматизация, черты стран, военный ИИ (`ai.gd`,
  `ai.cpp`), планирование наступления, `balance_check`.
- `peace.md` — конец войны: капитуляция в оккупацию, вклад, мирные переговоры,
  сопротивление и законы на чужих землях, свобода марионеток (`peace.gd`,
  `occupation.gd`, `puppets.gd`).
- `politics.md` — политическая власть, стабильность, поддержка войны, гарантии
  (перевес, событие «вступиться или нет»), баффы сторон войны (`politics.gd`).
- `economy.md` — ресурсы, торговля, договоры, блокада (`economy.gd`).
- `supply.md` — снабжение по узлам районов: нагрузка, улучшение, присоединение, грузовики (`supply.gd`); Испания.
- `science.md` — наука: слоты исследований, дерево технологий, бонусы родов
  войск, флота и авиации, ИИ науки, окно дерева (`tech.gd`, `tech_view.gd`).
- `save.md` — главное меню, сохранение, загрузка, автосохранение (`save.gd`).
- `engine.md` — фоновый поток симуляции, конвейеры ввода и экрана, дивизии в
  плоских массивах, ядра GDScript/C++, упреждение (`spec.gd`), скорости, замеры.
- `build.md` — сборка C++ (GDExtension) и APK.
- `map.md` — карта мира, провинции, морские зоны, воздушные районы, `build_map.py`.
- `ui.md` — оформление «Досье и архив», ШАБЛОН ОФОРМЛЕНИЯ окон, иконки, шейдер
  карты и её качество, фишки, звук, отчёт с телефона.

- Ориентир по механикам, плотности карты и темпу — стратегии жанра (Hearts of

## Всегда
- Изменение мира из интерфейса — через `game.act(cb)` (или между
  `game.world_lock()` / `game.world_unlock()`): симуляция идёт в фоновом потоке.
- Горячие ядра есть в двух вариантах (GDScript и C++), результаты обязаны
  совпадать до бита; игра детерминирована (`sim_bench`, `save_check`).
- Новое поле мира попадает в сохранение само; новый внутренний класс мира —
  дописать в `SaveGame._classes`; описания фокусов и событий в ходе партии на
  месте не менять (`save.md`).
- Сторонние материалы — только со свободной лицензией, дополнять
  `assets/CREDITS.md`; новые окна — по утверждённому шаблону (`ui.md`).
- Цифры и тексты — свои, по истории; ориентир по механикам — жанр.

## Ограничения по содержанию
Реальная история (страны, границы, лидеры, события, даты) — можно. Ассеты и
тексты коммерческих игр (графика, деревья фокусов, тексты событий, музыка,
название) — не копируем; всё оформление и тексты пишем сами.

## Правила многопоточности (см. `scripts/sim/parallel.gd`)
- Параллельная фаза = «посчитать параллельно → применить в главном потоке по
  порядку». Задачи только читают мир и пишут в свой слот `results[i]`.
- Случайность в задачах — только `Parallel.rng(seed, day, index)`.
- Не читать из потоков константные `Array/Dictionary` скриптов (в 4.3 гонки и
  падения) — копировать таблицы в Packed-массивы мира.
- Массивы чужого объекта (`world.p_controller`) выносить в локальную
  переменную один раз на задачу; соседство — CSR (`adj_start/adj_list`).
- Мелкую работу не распараллеливать (порог `min_count`, запуск группы ~50 мкс).
- Пока идёт фоновая группа (`Parallel.start`), `Parallel.run` выполняется в
  главном потоке. Фоновые задачи читают только переданную им глубокую копию
  данных (`duplicate(true)`): часть записей в массивы мира идёт на месте.
- Литералы-массивы (`["a", "b"][i]`) в коде, который идёт в потоках, — это
  тоже общие константы: не использовать.
- `arr[k].append(x)`, где `arr[k]` — Packed-массив внутри Array, копирует его
  целиком на каждый вызов: собирать в обычный Array, потом конвертировать.

## GDScript
- Упакованные массивы (Packed*) передаются по ссылке: из кэша отдавать
  `duplicate()`, если получатель меняет массив на месте.
- `:=` не выводит тип из нетипизированных значений (элементы `Array`, поля
  через нетипизированную переменную) — писать `var x: int = ...`.
